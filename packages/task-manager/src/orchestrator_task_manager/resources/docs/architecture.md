# Внутренняя архитектура Task Manager

**Статус:** реализованная структура пакета, 2026-09-17. Публичный контракт описан в [contract.md](contract.md), использование — в [usage.md](usage.md).

## Модули и зависимости

| Модуль | Ответственность |
| --- | --- |
| `contracts.py` | TaskError, константы, базовая валидация, UTC и контекст событий |
| `migrations.py` | Схема и последовательный транзакционный запуск миграций |
| `repository.py` | SQLite, фильтры, версии, атомарные snapshot/event/operation, tombstone |
| `service.py` | Единый жизненный цикл, guards, документы, claim/lease, решения и retention |
| `storage_transfer.py` | Экспорт, backup/restore, проверка копий и временные файлы |
| `diagnostics.py` | Read-only диагностика снимка с переданным ready-guard |
| `task_manager.py` | Совместимые переэкспорты прежних классов и констант |
| `task_cli.py`, `task_web.py` | CLI и локальная read-only панель |
| `task_mcp.py` | JSON-RPC MCP stdio-адаптер с фиксированным project root |

Клиент использует `from orchestrator_task_manager import TaskManagerService, TaskError`; `SQLiteTaskRepository` также остаётся экспортируемым. Старые импорты из `orchestrator_task_manager.task_manager` возвращают те же классы. Дополнительные модули — внутренняя организация, не требование к агенту-потребителю.

Зависимости направлены вниз: contracts не импортирует проектные модули; migrations зависит от contracts; repository — от contracts/migrations; storage_transfer и diagnostics — от инфраструктуры хранения; service — от этих компонентов. Инфраструктура не импортирует service или фасад. Пакет не зависит от ядра Orchestrator и не получает новых внешних зависимостей.

## Транзакции и guards

Сервис передаёт изменение в `repository.mutate`. Проверка версии, callback изменения, snapshot, событие и результат идемпотентности остаются в одной `BEGIN IMMEDIATE` транзакции. Не выносите callback за транзакцию.

Внутренняя граница хранения `read_transaction` предоставляет соединение с `PRAGMA query_only=ON` и `BEGIN DEFERRED` только внутри контекста. Экспорт и диагностика читают единый снимок. SQLite запрещает запись, ошибка становится TaskError. Это не новый способ изменения задач для агента. Сервис не выполняет SQL и не вызывает приватные методы репозитория.

Backup использует SQLite backup API; restore самостоятельно запускает миграции временной копии. Safety copy, уникальные временные файлы и требование остановить другие процессы сохранены. Схема остаётся версии 5; ручная миграция базы из-за разделения файлов не нужна.

Ready-guard остаётся единым методом сервиса: диагностика получает callback, а не копирует правила. Проверки файлов и потоковый SHA-256 остаются рядом с жизненным циклом. Mixin-классы для групп переходов не вводятся.

## Разработка

CLI — адаптер над публичным сервисом, а не отдельная реализация правил задачи. Команды переноса объявляются и выполняются через один реестр `TRANSFER_COMMANDS`: `export → export_state`, `backup → backup`, `restore → restore`. Совпадение названия команды с именем метода нельзя предполагать. Регрессионные subprocess-тесты проверяют JSON-ответы, ошибки назначения и backup/restore на временных проектах.

MCP — тонкий транспортный адаптер: `initialize` согласует версию протокола, `tools/list` публикует схемы, `tools/call` вызывает публичный сервис. Экземпляр создаётся с одним абсолютным `project_root`; инструмент не может сменить его. Ошибка `TaskError` возвращается как структурированный результат MCP с `isError: true`, а неожиданный сбой не закрывает stdio-сессию. Никакой записи в stdout кроме JSON-RPC нет; диагностические сообщения идут в stderr.

Файловые аргументы MCP для `task_export`, `task_backup` и `task_restore` разрешаются относительно project root и проверяются после `resolve`; путь за пределами корня отклоняется до вызова сервиса. Это ограничение относится только к MCP-адаптеру и не меняет существующий CLI/API-контракт.

Подменяйте функцию в модуле её использования: `_sha256` в service, `os.replace` и `shutil.copy2` в storage_transfer. Переэкспорты приватных helper-функций сохраняют импорт, но monkeypatch старого фасада не перенаправляет вызовы реализации и не является публичным контрактом.

Тесты проверяют предметные сценарии, прежние импорты, параметры API по снимку до переноса, зависимости, закрытие read-only соединения и согласованность диагностики при конкурентной записи. Полный прогон и изолированная проверка wheel обязательны. Перенос файлов не является оптимизацией; скорость проверяется одинаковыми замерами до/после на временных проектах.
