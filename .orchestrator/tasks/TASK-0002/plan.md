# План TASK-0002: минимальные контракты Graph Runtime

## Цель

Зафиксировать переносимые контракты `Graph`, `Node`, `Artifact`, `WorkflowRun`, результата узла и паузы для одного агента в одной real-time сессии. Контракты должны разблокировать реализацию TASK-0003 и Artifact Repository TASK-0014 без введения второго источника состояния.

## Объём

1. Сверить действующие документы `docs/architecture/`, `docs/graph/`, `docs/development/` и согласованный real-time дизайн.
2. Создать русскоязычный действующий контракт Graph Runtime с обязательными полями, инвариантами, ошибками и минимальным API.
3. Описать границы владельцев данных: Graph Runtime хранит текущий запуск в памяти, Task Manager хранит состояние задачи и ссылки, платформенные адаптеры выполняют операции.
4. Зафиксировать детерминированные правила маршрутизации, допустимые исходы узлов, `needs_input`, `blocked`, `failure`, отмену и защиту от неизвестных результатов.
5. Отдельно исключить из v1 многосессионную координацию, Executor Loop, runtime SQLite, автоматическое восстановление и распределённые гарантии.
6. Обновить связанные действующие документы и навигацию, чтобы они ссылались на единый контракт.

## Артефакты и проверка

- действующий контракт: `docs/architecture/graph-runtime-contract.md`;
- актуализированные ссылки в `workflow-run.md`, `workflow-pause-resume.md`, `state-and-storage.md`, `docs/README.md` и `roadmap.md`;
- проверка локальных Markdown-ссылок и `git diff --check`;
- проверка отсутствия обязательных полей, которые противоречат границе v1;
- результат анализа и команды проверок в `docs/worklog.md`.

## Границы завершения

Задача не создаёт runtime-код, отдельное хранилище запусков, графовую библиотеку или Executor Loop. После утверждения контракта TASK-0003 может реализовать минимальный in-memory движок, а TASK-0014 — репозиторий артефактов, не меняя этот API без отдельного уточнения.
