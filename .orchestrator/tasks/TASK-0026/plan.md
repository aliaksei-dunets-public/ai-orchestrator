# План TASK-0026

**Статус:** первый stdio-срез реализован; задача ожидает пользовательской приёмки.

## Зафиксированное решение

- Код MCP-адаптера поставляется одним переиспользуемым Python-пакетом.
- MCP запускается через локальный `stdio`.
- Каждый проект получает отдельный экземпляр MCP-процесса, запущенный с фиксированным `project_root`.
- Состояние проектов не смешивается: каждый экземпляр использует только `<project_root>/.orchestrator/state/tasks.sqlite3`.
- `project_root` задаётся при запуске и не меняется инструментальным вызовом.
- MCP вызывает только публичный `TaskManagerService`; прямой SQL, собственное хранилище и дублирование guards запрещены.
- CLI сохраняется как резервный интерфейс диагностики и работы.

## Этапы реализации

1. Уточнить MCP-инструменты и схемы аргументов для чтения, создания, подготовки, исполнения, приёмки, архивации, переноса и диагностики.
2. Реализовать stdio-сервер как тонкий адаптер над публичным Python API.
3. Ограничить корень проекта при старте и проверить защиту от выхода за разрешённый проект.
4. Сохранить `expected_version`, `operation_id`, структурированные `TaskError` и запрет слепых повторов.
5. Проверить реальным MCP-клиентом полный lifecycle, ошибки, конфликт версий, неопределённый результат, Unicode, перезапуск и CLI fallback.
6. Документировать установку и подключение одного и нескольких проектов; измерить p50/p95.

## Результаты реализации

- Добавлен `task_mcp.py` и консольный entry point `orchestrator-task-manager-mcp` без новых зависимостей.
- Реализованы MCP lifecycle, `tools/list`, `tools/call`, 35 инструментов, структурированные результаты/ошибки, фиксированный root и защита файловых путей.
- Добавлен полный subprocess-тест от создания до архивации, тест изоляции проектов, ошибок версии и выхода за root.
- Benchmark `benchmark_task_mcp.py --count 100`: startup initialize p50 не измерялся отдельно, фактический startup — 124.702 ms; тёплый `task_get` p50 — 0.350 ms, p95 — 0.551 ms.
- Проверки: 65 тестов Task Manager, 5 тестов ядра, изолированный wheel с Python `-S`, `validate` живого проекта и `git diff --check`.

## Границы

В первый срез не входят HTTP daemon, общий мульти-тенантный процесс, кэш карточек, пакетные мутации, изменение схемы SQLite и интеграция с внешним Task Tracker или Graph Runtime.

Основание решения: пользователь подтвердил необходимость закрепить вариант «один общий пакет, отдельный stdio-экземпляр на проект, раздельное состояние» в задаче и плане.
