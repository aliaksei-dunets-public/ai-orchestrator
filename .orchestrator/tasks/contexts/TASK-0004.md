# TASK-0004 — English-first project language migration

## Исходный запрос

Перевести весь проект на английский язык. Гайды и инструкции пользователя должны
иметь русскую и английскую версии. Агент Knowledge Graph должен исключать русскую
документацию и работать только с английской версией.

## Цель

Сделать английский единственным каноническим языком кода, конфигурации, схем,
registries, workflows, skills, specifications и maintainer-документации, сохранив
полные русские и английские пользовательские материалы и детерминированно исключив
русские документы из graph sources и retrieval.

## Проблема или потребность

В репозитории смешаны русские и английские нормативные документы, планы, skills,
Task Context contracts и пользовательские guides. `knowledge-curator` и retrieval
сейчас проверяют существование и digest source, но не его язык, поэтому русская
документация может попасть в graph provenance и Context Pack.

## Текущее поведение

Каноническими источниками считаются русские specification paths, часть системных
skills и guides остаётся на русском, а отдельной language policy нет. Graph
источник классифицируется по расположению и типу документа, без English-only
allowlist или отказа для Russian/mixed-language sources.

## Ожидаемое поведение

Английские canonical paths и тексты используются всеми внутренними компонентами.
Каждый пользовательский guide/instruction имеет English canonical и Russian
companion с reciprocal metadata. Shared language policy помечает Russian и mixed
sources как non-canonical/non-graph-eligible; `knowledge-curator`, graph API, CLI,
onboarding и retrieval применяют это правило одинаково.

## Анализ

Задача имеет deep/high-risk характер: она меняет source-of-truth paths, ссылки,
skill projections, validation contracts и graph provenance. В репозитории
подтверждены русские canonical specifications, guides, планы и системные skills;
`orchestrator/source_authority.py` и `orchestrator/retrieval.py` не имеют языкового
контракта. Свежий bounded context pack был получен до анализа; memory и graph
stores пусты, поэтому дополнительные project decisions не извлечены.

## Выбранный подход

Ввести единый `config/language-policy.json` и platform-neutral helper, перевести
внутренние canonical artifacts на английский, а user-facing материалы хранить в
раздельных English/Russian файлах с явным `language` и `translation_of`. Английские
файлы остаются единственными canonical graph sources; русские companions,
смешанные документы, неизвестный язык и отсутствие metadata отклоняются до graph
write. Процесс разделяется на policy/inventory, canonical translation, bilingual
docs, graph enforcement, skill/runtime translation, Health/release и acceptance.

## Рассмотренные альтернативы

- Смешивать русский и английский в одном файле — отклонено: graph agent не сможет
  детерминированно выбрать английские фрагменты без отдельного segment parser.
- Оставить русский canonical source и только добавить английские копии — отклонено:
  это сохраняет двуязычную source-of-truth и противоречит переходу проекта на
  английский.
- Фильтровать язык только эвристикой по символам — отклонено: это нестабильно для
  mixed documents, code fences и технических имён.
- Исключить только пути с `_ru` — отклонено: правило должно защищать API, CLI,
  onboarding и provenance также от metadata/path aliases и mixed sources.

## Объём задачи

### Входит в scope

- language policy, repository inventory и canonical-source manifest;
- перевод canonical specifications, architecture/ADR, plans, validation, README,
  roadmap, skills, workflows, runtime messages, tests и registries;
- English/Russian pairs для README, guides, migration и user-facing instructions;
- English-only Knowledge Curator/source authority/graph API/CLI/onboarding/retrieval;
- generated skill projections, documentation map, Health, release migration и
  acceptance evidence.

### Не входит в scope

- изменение бизнес-семантики Task Manager, Memory, Knowledge Graph, ontology или
  approval policy, кроме языкового enforcement;
- embeddings, vector search, UI, network synchronization или cross-project graph;
- автоматический перевод новых пользовательских проектов;
- удаление русских companions или исторических baseline files без migration policy;
- ручное редактирование `.codex/skills/` или `.agents/skills/`.

## Затрагиваемые компоненты

- `config/language-policy.json`, `config/defaults.yaml`, schemas и documentation map;
- `orchestrator/language_policy.py`, `source_authority.py`, `knowledge.py`,
  `retrieval.py`, `knowledge_cli.py`, `health.py`, `documentation.py` и task/runtime
  message modules;
- `docs/specifications/`, `docs/architecture/`, `docs/adr/`, `docs/guides/`,
  `docs/migrations/`, `docs/plans/`, `docs/validation/`, `README.md`, `ROADMAP.md`;
- canonical `skills/`, generated `.codex/skills/` and `.agents/skills/`, workflows,
  registries, templates and affected tests.

## Критерии приёмки

- AC1: Language policy и inventory классифицируют все canonical, bilingual,
  Russian-companion, generated и excluded paths без unclassified Cyrillic.
- AC2: Canonical code-facing и maintainer artifacts English-only, ссылки и contracts
  согласованы.
- AC3: User-facing README, guides, migration и instructions имеют English canonical
  и Russian companion с reciprocal links/metadata и эквивалентными командами.
- AC4: Graph API, CLI, onboarding и Knowledge Curator отклоняют Russian, mixed,
  unknown-language и metadata-less documentation sources.
- AC5: Retrieval не возвращает graph records с русской provenance; empty/irrelevant
  stores остаются valid no-op.
- AC6: Existing schema/API compatibility сохранена за пределами явно описанной
  language-policy migration.
- AC7: Focused/full tests, static inventory, documentation checks, security review и
  strict Health проходят без ERROR/CRITICAL.
- AC8: Migration/release documentation описывает path mapping, rollback и graph
  rebuild.

## Ограничения

- Python 3.11+ и standard library runtime.
- Platform-neutral core; platform behavior остаётся в profiles/adapters.
- `skills/` является canonical source для projections.
- Русские user-facing companions не являются graph sources.
- Не коммитить Task Registry operational state, proposals, indexes, backups,
  checkpoints или releases.
- Existing user changes сохраняются.

## Риски

- Семантическая ошибка при переводе contract text; mitigation: parity checks,
  specification tests и независимый review.
- Русский source проходит через обходной graph path; mitigation: shared policy,
  stable rejection codes и provenance/retrieval tests.
- Broken path/link migration; mitigation: reciprocal links, compatibility aliases,
  release smoke tests и rollback map.
- Drift между bilingual documents; mitigation: manifest, code-fence/command parity и
  Health findings.

## План реализации

- Реализовать `docs/plans/2026-07-28-english-first-language-migration.md` задачами
  1–7 последовательно: policy → canonical translation → bilingual docs → graph
  enforcement → skills/runtime → Health/release → acceptance.
- Перед каждым переходом сохранять manifest digest и запускать focused checks.
- После завершения выполнить full discovery, acceptance matrix, security/documentation
  review и strict Health Check.

## Plan Review

План покрывает language migration, bilingual user materials, English-only graph
policy, exact repository interfaces, compatibility, security, documentation,
rollback и executable validation. Рекомендуемый paired-file подход выбран потому,
что он позволяет graph retrieval использовать строгий English allowlist без
эвристического выбора фрагментов в mixed documents.

## Открытые вопросы

- Решение пользователя получено 2026-07-28: для bilingual guides используется
  модель двух связанных файлов (English canonical + Russian companion), а не один
  смешанный файл с двумя языковыми секциями.
