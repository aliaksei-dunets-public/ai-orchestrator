# TASK-0007 — Serial execution branch policy analysis

## User Request

In serial mode, prevent the orchestrator from creating or switching to a task
branch or Git worktree. Analyse the behaviour before planning, then implement
the approved plan.

## Goal

Make the serial execution policy explicit and testable while preserving the
existing runtime boundary: serial work remains in the current branch and
primary workspace, and task-owned branch/worktree lifecycle remains exclusive
to explicit `isolated_parallel` execution.

## Scope

### In Scope

- Declare the serial branch policy in the execution and backlog workflows.
- Add the same operating rule to the canonical Implementation Runner skill and
  regenerate managed platform projections through the skill installer.
- Add a regression contract test for serial policy, isolated routing, and
  skill distribution.
- Align canonical workspace documentation and record every required
  Documentation Manager disposition.
- Finalize, validate, and commit the approved task artifacts from the current
  serial branch.

### Out of Scope

- Add serial branch assignments, Git enforcement wrappers, or a runtime
  branch/worktree lifecycle.
- Force `main` checkout; a user-selected current branch remains valid.
- Change the `isolated_parallel` allocation, integration, or cleanup contract.
- Control user-operated or external Git clients outside orchestrator-managed
  agent execution.

## Problem or Need

TASK-0006 ran in the primary workspace and serial mode, but an agent manually
switched to `codex/task-0006-post-task-finalization`. That Git lifecycle was
not created by the serial runtime and had no serial merge step. The workflow
said only that serial used `main`, while the canonical execution skill did not
forbid manual task-branch operations.

## Current Behavior

`TaskManager.claim_next()` creates no assignment in serial mode and invokes
`_assign_isolated()` only for `isolated_parallel`. `WorktreeManager.create()`
is reachable only from isolated assignment. The execution workflow names the
serial workspace but does not define the current-branch or no-manual-branch
rule for an agent.

## Expected Behavior

Serial workflow and agent instructions require the primary workspace and the
already selected branch. They forbid agent-initiated task-branch creation,
branch switching, worktree creation, integration, and cleanup. The existing
isolated path is unchanged and remains the only path that may use a registered
task-owned branch or worktree.

## Analysis

- The serial runtime already has no branch or worktree allocation defect.
- Git reflog identified the TASK-0006 branch as a manual agent checkout; Git
  worktree listing contained only the primary workspace.
- The missing boundary is declarative, so a workflow, canonical skill, and
  contract test are sufficient. A runtime guard would either duplicate state
  or incorrectly override a legitimate user-selected branch.
- Fresh bounded retrieval returned only the finalization decision MEM-0001;
  there were no relevant Knowledge Graph records.
- The user explicitly approved revision 2 of this English-first context and
  implementation after plan validation.

## Selected Approach

Use a declarative serial policy in both workflows and the canonical
Implementation Runner, protect it with a regression contract test, regenerate
managed projections through their owner, and update only the affected
canonical documentation. Do not modify runtime branch allocation code.

## Alternatives Considered

- **Store a serial branch assignment in the Task Registry:** rejected because
  serial has no assignment contract and this cannot distinguish a user branch
  from an agent-created one.
- **Force `git checkout main` before serial work:** rejected because it changes
  user Git state and breaks valid feature-branch workflows.
- **Use an undocumented convention:** rejected because it cannot be tested or
  preserved across future agents.

## Affected Components

- `workflows/task-execution.yaml` and `workflows/backlog-loop.yaml`
- `skills/bundled/implementation-runner/SKILL.md` and generated projections
- `tests/contracts/test_serial_execution_branch_policy.py`
- Workspace execution specifications, migration, ADR, and component contract
  documents selected by `config/documentation-map.json`

## Constraints

- Use the current `main` workspace for this serial task; create no branch or
  worktree.
- Preserve unrelated files and do not commit Task Registry state or locks.
- Use English canonical artifacts and regenerate projections rather than
  editing them directly.
- Run finalization before task completion and commit.

## Risks

- Declarative text cannot prevent external Git UI actions; scope the guarantee
  to orchestrator-managed agents and test that contract.
- Ambiguous wording could force `main`; assert that serial preserves the
  current branch.
- Projection drift can hide the canonical skill change; regenerate and run the
  distribution contract.

## Acceptance Criteria

- Serial workflow declares the primary workspace, current branch, and forbidden
  task branch/worktree operations.
- The canonical Implementation Runner preserves the same boundary and limits
  task-owned Git lifecycle to registered isolated assignments.
- Runtime code remains assignment-free in serial and isolated behaviour remains
  unchanged.
- A regression contract test, affected existing contracts, documentation link
  checks, Task Registry validation, and Health Check pass.
- Required documentation dispositions, Knowledge Curator proposal, Memory
  Manager candidates, and a current ready finalization receipt exist before
  completion and commit.
