# TASK-0023: надёжность, агентский CLI и производительность

**Статус:** отчёт о реализованном срезе и проверках, 2026-09-16. TASK-0023 находится в awaiting_acceptance (version 17); финальная пользовательская приёмка отдельно от разрешения реализации.

## Реализованные изменения

- SHA-256 читает блоками до 64 KiB; get_document проверяет ровно прочитанные байты, сохраняет UTF-8 и прежние переводы строк.
- UTC единообразен для clock, lease, retention и меток времени; naive datetime означает UTC.
- Архив определяется структурно в SQL до LIMIT, включая JSON с другой расстановкой пробелов; fallback работает без JSON1.
- summary агрегирует выбранные карточки в SQL и отдельно считает глобальные архив/tombstone.
- export/summary/validate используют единый read-снимок; validate заменяет запросы по каждой задаче общими выборками статистики событий.
- Файловые отказы дают предметные TaskError, уникальные временные файлы не затрагивают чужие .tmp. Restore проверяет схему/integrity/ссылки, мигрирует только staged-копию и сохраняет текущую БД через SQLite backup. Восстановление из .pre-restore не перезаписывает сам источник.
- accept_task атомарно регистрирует явную приёмку текущей ревизии и завершает задачу; при отказе guard решение не остаётся в карточке. Повтор purge по operation_id работает после удаления snapshot.
- CLI покрывает подготовку, артефакты, claim/lease, блокеры, ожидание, решения и приёмку. Есть expected-version, JSON-ошибки разбора и подсказки, api с фактическими сигнатурами, summary и table для чтения человеком. Старые JSON-ответы и коды выхода сохранены.
- Гайд содержит полную таблицу методов и CLI; skill направляет агента к профильным командам, явной версии и контролируемому повтору. Обычный TypeError неправильной Python-сигнатуры сохранён.

## Уточнение исходного аудита

Исходное предположение о скрытии задачи из-за текста `"archive": {` слишком широкое: кавычки внутри JSON-строки экранируются. Регрессия подтверждает сохранение таких текстовых полей, но действительная проблема прежнего фильтра — зависимость от пробелов сериализации и последующая фильтрация уже ограниченной LIMIT страницы. Исправление проверено на minified-снимке архивной задачи.

## Условия замеров

Windows 11 10.0.26200, Python 3.12.14, SQLite 3.53.1. Каждый размер — новый временный проект, неархивные created-задачи с одним событием. Чтения повторены 10 раз в одном процессе; SHA-256 — 5 раз для каждого размера. В таблицах указаны **p50 / p95 в миллисекундах**; при малом числе повторов p95 здесь близок к максимуму, а не является устойчивой оценкой хвоста. Время запуска Python/CLI не включено. Последний замер выполнялся без параллельного тестового прогона.

## Практические границы

Замеры не доказывают характеристики больших историй, одновременных workers, холодного диска и других платформ. Guards ready дополнительно читают план с диска. get_document и export возвращают/формируют полное содержимое, поэтому расход памяти зависит от документа и объёма экспорта. Restore выполняется после остановки других клиентов; схема координации живых процессов не добавлена. Автоматическое восстановление внешней работы по истёкшему claim по-прежнему требует отдельного решения runtime.
