# TASK-0025: исправление CLI и интерфейс агента

**Статус:** подтверждённый дефект исправлен и проверен; результат подготовлен к пользовательской приёмке. MCP-адаптер не реализован.

## Исправление

[Аудит Luna](2026-09-17-task-manager-agent-audit-luna.md) зафиксировал одну подтверждённую проблему P1: CLI export вызывал отсутствующий service.export. Теперь parser и dispatch используют общий TRANSFER_COMMANDS: export → export_state, backup → backup, restore → restore. Ошибка устранена в месте вызова, широкий перехват AttributeError не добавлялся. Публичные сигнатуры, схема 5, транзакции, guards и зависимости не менялись.

Добавлены три subprocess-регрессии:

1. Экспорт обычной и архивной карточек, UTF-8 JSON, счётчики, повторная запись; неизменность карточек, версий и истории.
2. Назначение поверх рабочей SQLite и существующего каталога: validation_failed/repository_failure, JSON stderr, код 2 без traceback. База и пользовательский marker сохранены, временный файл очищен.
3. Соответствие реестра публичным методам/parser; CLI backup/restore возвращает карточку и историю, создаёт safety copy и не меняет исходный backup. Restore выполнялся только на временном проекте.

## Какой адаптер и какой вариант лучше

Адаптер переводит структурированный вызов инструмента агента в существующий публичный TaskManagerService. Например, tasks_create вызывает create_task, tasks_archive — archive_task с expected_version. Это не новый Task Manager, SQLite-репозиторий, внешний Task Tracker Adapter TASK-0018 или Graph Runtime.

Для внешнего агента Codex рекомендован следующий отдельный срез: локальные MCP-инструменты через stdio поверх Python API с процессом, обслуживающим последовательные вызовы. Это убирает shell-экранирование и запуск Python на каждую команду. Внутри Python-оркестратора предпочтительны встроенные инструменты, непосредственно вызывающие API, без MCP-транспорта. Сегодня реализованы только CLI и Python API; CLI остаётся резервным путём.

Основание — замеры аудита одной карточки: около 0,25 мс тёплый API get и 149 мс отдельный CLI show. CLI включает startup/parser/создание сервиса, API их исключает. MCP-задержки ещё не измерены; ускорение всего workflow из этих чисел не следует.

Будущий интерфейс должен сохранить version guards, поддерживаемую идемпотентность и структурированные ошибки, не делать слепых повторов и не подменять пользовательскую приёмку. Проверяются реальный клиент, lifecycle, конфликт/неопределённый результат и перезапуск. Компактные JSON-проекции — последующее предложение; текущий list возвращает полные карточки.

[Варианты, границы и проверки](../plans/2026-09-17-task-manager-agent-interface-design.md) зафиксированы с использованием brainstorming. Новый транспорт, сервер, зависимости, кэш и пакетные мутации в TASK-0025 не добавлены. Существующие незакоммиченные изменения сохранены; отдельный коммит поверх незавершённого среза не создавался.
