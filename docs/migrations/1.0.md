# Migration to 1.0

## Supported inputs

The supported upgrade path is from specification 0.4 / Task Layer 0.3 prototypes using schema version 1. Schema version 1 registries and Task Contexts remain compatible; operational `tasks.json` stays project-local and is not overwritten by managed installation.

## Compatibility window

Public Python APIs, CLI exit codes, Task Context schema version 1, registry schema version 1, review results, approvals, memory entries, and profile contracts are stable throughout the 1.x line. Incompatible changes require a new schema/API version and an explicit migration.

## Known limitations

- Task Manager supports one modifying process; interprocess locking is a future optional capability.
- Platform profiles expose maturity and validation evidence. Codex is stable; Google Antigravity, GitHub Copilot VS Code and Claude VS Code remain experimental until independent native smoke runs satisfy DEC-005.
- ABAP/RAP external commands require approval and compatible vendor tooling.
- Exact token savings require provider usage counters; the additive telemetry contract preserves unknown values instead of estimating them.

## Rollback

Restore the previous managed `.orchestrator/core` directory or standalone installation, then restore tracked Task Context and project-owned files from Git. Do not roll back or hand-edit `tasks.json` while a modifying Task Manager process is active.
