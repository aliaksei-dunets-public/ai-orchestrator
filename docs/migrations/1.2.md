# Migration to 1.2

## Supported inputs

The supported upgrade path is AI Orchestrator 1.1.x with schema-version-1
registries, Task Contexts, memory entries, and knowledge nodes/edges. Existing
public Python calls remain readable through compatibility adapters.

Run migration as a preview and bind approval to its exact `plan_hash`. Apply
refuses changed sources or targets:

```powershell
python -m orchestrator context --root . --mode standard
```

The Python migration API is
`plan_migration(root)`, `apply_migration(root, plan, approved_plan_hash=...)`,
and `rollback_migration(root, plan_hash)`.

## Target layout

Tracked canonical files:

- `.orchestrator/memory/entries.jsonl`;
- `.orchestrator/memory/events.jsonl`;
- `.orchestrator/memory/approvals.jsonl`;
- `.orchestrator/knowledge/ontology.json`;
- `.orchestrator/knowledge/nodes.jsonl`;
- `.orchestrator/knowledge/edges.jsonl`.

Ignored operational files:

- `.orchestrator/memory/proposals/`;
- `.orchestrator/knowledge/indexes/`;
- `.orchestrator/migrations/backups/`.

## Compatibility window

Schema-version-1 memory entries, graph nodes/edges, Task Contexts, registries,
and existing Python function signatures remain supported throughout 1.x.
Project-aware calls add relative provenance and digests; legacy absolute
provenance is accepted only when it resolves safely inside the project.

## Known limitations

- One modifying process is supported; interprocess locks are not provided.
- Retrieval is lexical and may miss semantic synonyms unless canonical terms or
  graph relations connect them.
- No embeddings, vector database, network synchronization, web UI, or
  cross-project shared memory is included.
- Character budgets bound serialized context; provider token counts remain
  observational telemetry.

## Rollback

Stop task execution, call `rollback_migration` with the applied plan hash, and
verify restored digests. If workflow integration must also be rolled back,
restore the 1.1 Core and platform projections together. Do not delete canonical
history manually; use disable/supersede events for content corrections.
