# Migration 1.4: Task finalization

## Изменение completion contract

Новые переходы в `done` требуют completion-ready Task Finalization receipt.
До commit execution workflow должен:

1. собрать normalized changed paths;
2. получить documentation dispositions для всех mapped documents;
3. получить explicit Knowledge Curator proposal, включая допустимый empty no-op;
4. создать/promote memory proposals либо разрешить hash-bound approvals;
5. записать receipt через `orchestrator-task finalize`.

Минимальный `finalization.json`:

```json
{
  "changed_paths": ["orchestrator/example.py", "docs/example.md"],
  "documentation_dispositions": [
    {
      "document": "docs/example.md",
      "status": "updated",
      "reason": "",
      "evidence_ref": "docs/example.md"
    }
  ],
  "knowledge_proposal": {
    "schema_version": 1,
    "nodes": [],
    "edges": []
  },
  "memory_candidates": []
}
```

После commit:

```powershell
.\.venv\Scripts\orchestrator-task.exe complete TASK-0006 `
  --finalization-receipt .orchestrator/tasks/finalization/TASK-0006.json
```

Для isolated worktree сохраняются обязательные `--commit-evidence` и
`--repository-root`.

## Совместимость

- Existing `done` records без `finalization` остаются валидными для read/list,
  Health и migration.
- Новый вызов `complete` без receipt завершается
  `FINALIZATION_REQUIRED`/exit code `10`.
- `cancel` не требует receipt и сохраняет checkpoint.
- Receipt хранится в `.orchestrator/tasks/finalization/` и исключается из Git.
- Task Registry хранит только receipt hash, changed-paths digest и completion
  timestamp.

## Pending approvals

Instruction и non-authoritative memory candidates создают proposals, но не
canonical entries. При отсутствии approval receipt имеет
`memory_status=waiting_user` и `ready_for_completion=false`; backlog
останавливается до commit. После approve или reject finalization запускается
повторно с теми же inputs и idempotently переиспользует proposal.

## Rollback

Не удаляйте canonical memory history или knowledge records вручную. До commit
можно удалить только task-owned operational receipt и повторить execution.
После commit используйте обычный Git revert для runtime/docs/graph changes,
`disable`/`supersede` для append-only memory и новый graph proposal для
коррекции knowledge.
