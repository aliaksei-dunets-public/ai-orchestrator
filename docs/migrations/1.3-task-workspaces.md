# Migration 1.3: Task workspaces

## Совместимость

Существующие Task Registry records без `assignment` остаются валидными и
выполняются в `serial` mode. По умолчанию используется:

```yaml
execution:
  mode: serial
  max_workers: 1
  worktree_root: .orchestrator/worktrees
```

## Включение isolated parallel

Для нового run задайте уникальный `run_id`, `max_workers` от 2 до 16 и
`worktree_root`. Первая задача должна быть выполнена и закоммичена в main.
После этого Task Manager может назначить backlog-задачи в task-owned worktrees.

Пример:

```powershell
.\.venv\Scripts\python.exe -m orchestrator.task_cli claim-next --json `
  --mode isolated_parallel --run-id release-13 --max-workers 3 `
  --worktree-root .orchestrator/worktrees --repository-root .
```

Для isolated task команда `complete` требует полный commit SHA:

```powershell
.\.venv\Scripts\python.exe -m orchestrator.task_cli complete TASK-0007 `
  --commit-evidence <40-character-sha> --repository-root .
```

Assignment можно проверить через `orchestrator workspace inspect TASK-ID`.
Cleanup требует terminal outcome и удаляет только worktree с совпадающим
ownership manifest. Failed worktrees сохраняются.

## Rollback

Остановите isolated run, сохраните незавершённые worktrees и переключите
`execution.mode` обратно на `serial`. Не удаляйте worktree вручную, пока его
ветка и ownership manifest не проверены. Registry records с assignment можно
оставить для recovery; legacy serial records не требуют преобразования.
