# Migration to 1.1

## Supported inputs

The supported upgrade path is from AI Orchestrator 1.0.x with schema version 1
registries and Task Contexts. The Task Registry schema remains version 1, but
registered Context paths move under `contexts/` and checkpoints move under
`checkpoints/`.

Before starting the upgraded runtime:

1. Move each `.orchestrator/tasks/<TASK-ID>.md` to
   `.orchestrator/tasks/contexts/<TASK-ID>.md`.
2. Change each registry `context` value from `<TASK-ID>.md` to
   `contexts/<TASK-ID>.md`.
3. Move checkpoints that belong to unfinished tasks to
   `.orchestrator/tasks/checkpoints/<TASK-ID>.checkpoint.lock`.
4. Remove checkpoints for tasks already marked `done`; retain checkpoints for
   `cancelled` tasks when diagnostic history is required.
5. Replace `.orchestrator/tasks/*.lock` in `.gitignore` with
   `.orchestrator/tasks/checkpoints/`.

## Skill layout

Canonical skills moved from `skills/<id>/` to one of:

- `skills/system/<id>/`;
- `skills/bundled/<id>/`;
- `skills/optional/<id>/`.

Consumers must resolve canonical paths through `registries/skills.json` rather
than construct them from an ID. Platform projections remain flat by skill ID.
System and bundled skills are installed by default; optional skills are absent
until explicitly selected.

## Project configuration

Approved optional skills are stored in tracked `.orchestrator/skills.json`.
When the file is absent, the optional selection is empty. Project-owned skills
may be stored in tracked `.orchestrator/project-skills/<new-id>/`; an ID that
collides with any shipped skill is rejected.

Before upgrading, preserve project-owned files and the previous platform
projection. After upgrading, synchronize the projection from the 1.1 core and
run strict Health Check. Do not copy old optional projections into the new
default set.

## Compatibility window

Task Context contents, Task Registry schema and workflow IDs remain compatible.
Task Context and checkpoint filesystem paths intentionally change and require
the migration above. The canonical skill filesystem layout also changes;
registry-based skill consumers remain compatible without special handling.

## Known limitations

- Optional selection has no dependency solver or independent package versions.
- Project-owned skills must use a unique ID and are not automatically rebased.
- Technology detection only recommends optional skills; approval and
  synchronization remain explicit actions.

## Rollback

Restore the 1.0.x core and its platform projection together. Keep
`.orchestrator/skills.json` and `.orchestrator/project-skills/`; 1.0 ignores
them, and they can be reused after returning to 1.1. Before running the 1.0 Task
Manager, move `contexts/<TASK-ID>.md` back to the tasks root and remove the
`contexts/` prefix from registry values. Never hand-edit generated platform
copies as a rollback mechanism.
