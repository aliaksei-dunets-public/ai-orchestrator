# Orchestrator — проектные материалы

## Новое направление от 2026-09-17

[Orchestrator Agent](architecture/agent-centric-orchestration.md) теперь владеет оркестрацией; Workflow Graph задаёт политику, а код предоставляет детерминированные primitives. [Project Knowledge Service](architecture/project-knowledge-service.md) использует Graphify skill текущего host-agent для единого Project Knowledge Graph кода и долговечной документации; отдельный documentation graph и новый semantic backend для v1 не создаются. Неизменяемый Task Manager остаётся источником истины с SQLite; файловая карточка и обязательная specification не возвращаются.

Первый явный Python process API уже реализован: [контракт AgentGraphRuntime](architecture/agent-runtime-contract.md), [guide](guides/agent-runtime.md), [результаты TASK-0028](reports/2026-09-17-agent-runtime-v1.md). Callback GraphRuntime/PreparationWorkflow удалены в TASK-0034; [миграция](guides/workflow-runtime.md) описывает переход на единственный агентский путь. Новый [AgentPreparation](architecture/agent-preparation.md) связывает явные агентские results с artifacts и ready без claim; [guide](guides/agent-preparation.md), [отчёт](reports/2026-09-18-agent-preparation-v1.md). Реализован [Knowledge Service с Graphify adapter](guides/project-knowledge.md), real initial load и bounded MCP query; [отчёт TASK-0030](reports/2026-09-18-project-knowledge-service-v1.md). Добавлены [AgentExecution/preflight и work units](architecture/agent-execution.md), [guide](guides/agent-execution.md), [отчёт TASK-0016](reports/2026-09-18-agent-execution-v1.md). Installed Agent skill пока отсутствует; full execution gates реализованы, см. [контракт](architecture/execution-gates.md) и [guide](guides/execution-gates.md). Перед работой читайте [исходную оценку](reports/2026-09-17-agent-centric-graphify-assessment.md), [подтверждённый дизайн миграции](plans/2026-09-17-agent-centric-graphify-migration-design.md) и [актуальный roadmap](roadmap.md). Остальные implementation contracts создаются по этапам.

Общий [обзорный граф Orchestrator](architecture/orchestrator-graph-overview.md) показывает фактическую связь подготовки, work units, execution gates и пользовательской приёмки.

[Дизайн конфигурации workflow](plans/2026-09-18-workflow-config-subgraphs-model-policy-design.md) объединяет прежние решения о подграфах, моделях и настройках проекта. TASK-0036 реализует первый [конструктор](architecture/workflow-builder.md): TOML/catalog/композицию/overrides, builder skill и локальный HTML-инспектор; [guide](guides/workflow-builder.md). TASK-0037 добавляет [explicit исполнение](architecture/workflow-execution.md), host model adapters, передачу артефактов, registered roles и preflight snapshot binding; [guide и локальный пример](guides/workflow-execution.md).

Здесь собраны архитектурные материалы нового графового оркестратора. Большинство импортированных документов пока не подтверждают наличие работающего ядра. Статус каждого документа показывает, является ли он черновиком, принятым проектным решением или действующим контрактом. Реализованные срезы описаны в [контракте настройки проекта](architecture/onboarding.md), [интеграционной границе Task Manager Service](architecture/task-manager.md), [контракте Graph Runtime](architecture/graph-runtime-contract.md), [контракте Artifact Repository](architecture/state-and-storage.md), [гайде Workflow Runtime](guides/workflow-runtime.md), а также в [инструкции настройки](guides/onboarding.md), [инструкции просмотра задач](guides/tasks.md) и [гайде Artifact Repository](guides/artifact-repository.md). Они поставляются отдельными пакетами: [Onboarding](../packages/onboarding/README.md) и [Task Manager Service](../packages/task-manager/README.md). Core Graph Runtime v1 и Artifact Repository v1 реализованы в корневом исходном пакете; связывание подготовки описано ниже. AgentExecution и execution gates реализованы в исходном пакете. Полный устанавливаемый пакет ядра, persistence runtime и многосессионная координация остаются будущими этапами.

Действующие [контракт подготовки](architecture/agent-preparation.md) и [guide](guides/agent-preparation.md) описывают явные агентские results до `ready`. Прежние адреса callback-документов содержат инструкции миграции; общей транзакции и cross-session recovery нет.

## Содержание

Согласован принцип графа для одного агента в реальном времени и паузы в той же сессии; действующие детали закреплены в `docs/architecture/`. AgentGraphRuntime реализует in-memory процесс через `create_run`, `inspect_run`, `available_actions`, `submit_result`, `resume_wait` и `cancel`. Возможная [будущая функция координации нескольких запусков](architecture/runtime-coordination.md) вынесена отдельно и сейчас не реализуется.

Единая [граница состояния и хранения](architecture/state-and-storage.md) фиксирует SQLite как источник истины задач, Artifact Repository как владельца payload и отделяет документы от состояния запуска в памяти. AgentGraphRuntime, repository, AgentPreparation, AgentExecution и post-work-unit execution gates реализованы; установка общего agent/core bundle остаётся будущей работой.

Действующий контракт Graph, Node, Artifact, WorkflowRun и результата узла закреплён в [контракте Graph Runtime v1](architecture/graph-runtime-contract.md) в рамках TASK-0002; его core-реализация и пользовательская проверка выполнены в TASK-0003–TASK-0004.

- [`graph/`](graph/README.md) — импортированные материалы о маршрутизации запросов, управлении задачами, готовности к исполнению, цикле исполнителя и интеграции с трекерами;
- [`development/`](development/README.md) — импортированные материалы о контексте, анализе, планировании, реализации, проверках, тестах и документации;
- `context-knowledge/` — проект карты знаний и результаты её аудита.
- [Request Router → Task Creator](guides/request-flow.md) — реализованный первый входной срез без автоматического запуска Graph Runtime.
- [Agent Runtime](guides/agent-runtime.md) — запуск, pause/resume, блокировка и границы интеграции.
- [Инструкция первого запуска](guides/onboarding.md) — wizard-порядок для вопросов, настройки, установки и проверки Task Manager.

Актуальный снимок реализованного состояния для агента находится в [project-status.md](project-status.md). Эти импортированные проектные материалы пока написаны на английском. При внедрении их решения переводятся и актуализируются в русскоязычных действующих документах и гайдах. Прежний продукт сохранён в [`obsolete/`](../obsolete/README.md). Перед реализацией смотри [план миграции](roadmap.md) и [backlog с зависимостями](plans/2026-09-16-orchestrator-roadmap-backlog-design.md); выполненные работы фиксируются в [журнале](worklog.md).
