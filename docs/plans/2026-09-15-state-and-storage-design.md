# Согласование состояния и хранения

**Статус:** решение подтверждено пользователем, первый срез этапа 3.

## Решение

Каноническое состояние задач хранится только в SQLite Task Manager Service. Каталог `.orchestrator/tasks/` содержит человеческие документы Specification и Plan. Уточнение 2026-09-15: согласно [подтверждённому решению](2026-09-15-realtime-runtime-design.md), Graph Runtime v1 хранит процесс в памяти сессии; `.orchestrator/runs/` остаётся пространством будущих контрольных точек и рабочих файлов, а не обязательной базой runtime.

Рассмотрены файловое каноническое хранилище из импортированных материалов, SQLite с файлами документов и двойное хранение снимков в SQLite/YAML. Выбран второй вариант: он сохраняет уже реализованные транзакции и версии без второго источника истины. Файловый вариант заменён; двойная запись не вводится.

## Объём среза

Создать [единый контракт границы](../architecture/state-and-storage.md), отметить заменённые положения в затронутых исходных документах, обновить навигацию, roadmap и снимок состояния. Код, SQLite и `obsolete/` не изменять.

## Проверки

Проверить локальные ссылки в новых и изменённых документах, наличие предупреждений у исходных файлов с заменёнными положениями и `git diff --check`. Функциональные тесты не заменяют эти проверки: в этом срезе меняется документация, а не поведение.

## Следующий шаг
