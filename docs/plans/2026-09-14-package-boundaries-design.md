# Границы пакетов Onboarding и Task Manager Service

**Статус:** решение для реализации, 2026-09-14.

## Onboarding

`packages/onboarding/` повторяет структуру пакета Task Manager: `pyproject.toml`, `README.md`, `src/orchestrator_onboarding/`, `tests/`. Публичные входы — импорт `orchestrator_onboarding` и команда `orchestrator-onboarding`. В отличие от Task Manager, онбординг не объявляется изолированным от фреймворка: он проверяет структуру подключённого ядра, проектный skill и управляет интеграционными файлами целевого проекта. Протокол `preview/apply`, формат плана, хеш подтверждения, правила владения файлами и откат при ошибке остаются неизменными. Прямой запуск нового файла `.../src/orchestrator_onboarding/onboarding.py` сохраняет возможность первичной настройки без предварительной установки пакета; установленная команда удобнее для повторного использования.

## Task Manager Service

Самодостаточным должен быть не только код, но и поставка. Полный действующий контракт, инструкция пользователя и пример skill размещаются в ресурсах Python-пакета и включаются в wheel. `packages/task-manager/README.md` остаётся точкой входа и ссылается только на файлы внутри пакета. В корневых `docs/` остаются короткие интеграционные страницы, указывающие на пакетные первоисточники и связь с будущим Graph Runtime. Корневой проектный skill остаётся обнаруживаемым в `.agents/skills/`, но содержит лишь указатель на полный пример внутри Task Manager; так не поддерживаются две расходящиеся копии инструкций.

## Проверка

Тесты Onboarding переезжают в собственный пакет. Оба пакета устанавливаются и тестируются отдельно. Для Task Manager проверяется состав wheel: контракт, гайд и пример skill должны читаться через `importlib.resources` из установленного пакета. Для Onboarding проверяются консольная команда, прежние сценарии preview/apply и отсутствие изменений в схеме плана. Связанные README, инструкции, архитектура и журнал работ обновляются в этом же шаге.
