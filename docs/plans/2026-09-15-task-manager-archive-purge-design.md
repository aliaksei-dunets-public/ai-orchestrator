# Дизайн: архивация и физическое удаление задач

**Статус:** реализуется в `TASK-0013`.

## Решение

Архивация не меняет lifecycle-status: `completed` и `cancelled` остаются конечными статусами, а в снимке появляется обратимый блок `archive` с датой, актором, причиной и временем terminal-события. Архивные задачи скрыты из `list_tasks()` по умолчанию; `include_archived=True` возвращает их снова.

Физический purge разрешён только если одновременно выполнены условия:

1. задача архивирована;
2. статус — `cancelled`;
3. от terminal-события прошло не менее трёх календарных месяцев;
4. нет активного run или claim.

Purge удаляет snapshot и события одной транзакцией, но сохраняет минимальный tombstone в `purged_tasks`: ID, terminal/archived/purged timestamps и причину. ID повторно не используется.

## Интерфейсы

Публичные методы: `archive_task`, `unarchive_task`, `purge_task`. CLI получает команды `archive`, `unarchive`, `purge`; веб-панель остаётся read-only и добавляет просмотр архивных задач.

## Совместимость

Старые задачи без `terminal_at` получают его из исторического terminal-события при архивации. Существующие specification-артефакты не затрагиваются.
