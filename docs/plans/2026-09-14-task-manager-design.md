# Проект Task Manager Service

**Статус:** выбранное решение для первого среза, 2026-09-14. Размещение кода уточнено в [проекте выделения пакета](2026-09-14-task-manager-package-design.md); действующий контракт — [Task Manager Service](../architecture/task-manager.md).

## Решения

Task Manager Service — детерминированный владелец состояния задачи. Он не анализирует запрос, не выбирает узел графа и не выполняет код. Graph Runtime владеет состоянием запусков; задача хранит лишь ссылки на них. SQLite-база `.orchestrator/state/tasks.sqlite3` — канонический источник снимков задач, событий, версий и активных leases. Она не попадает в Git. Карточка Task Manager является каноническим определением, а `plan.md` — отдельным версионируемым планом реализации в `.orchestrator/tasks/TASK-xxxx/`. История в базе остаётся главным аудиторским журналом, а Git не является API изменения задачи.

## Модель и операции

Задача содержит ID, версию, название, тип, исходный запрос, цель, критерии приёмки, ограничения, статус, версию определения, ссылки на артефакты и запуски, блокеры, решения пользователя и временные метки. Статусы: `created`, `preparing`, `ready`, `active`, `awaiting_input`, `blocked`, `awaiting_acceptance`, `completed`, `cancelled`. Мутации требуют `expected_version`; один SQL-транзакционный коммит меняет снимок и добавляет событие. Конфликт версий — структурированная ошибка, не автоматическое слияние.

Выделенные команды создают и уточняют задачу, запускают подготовку, прикрепляют артефакты и Execution Package, переводят в `ready`, атомарно закрепляют за исполнителем, продлевают/освобождают lease, фиксируют блокеры и решения, завершают или отменяют задачу. Чтение предоставляет фильтруемый список, карточку, историю и список задач `ready`. Подготовка проверяет существование и хеш `plan.md`, привязку одобренного ревью и пакета к версии плана. `ready → active` разрешён только claim. Завершение требует свидетельства готовности и, по умолчанию, принятия пользователем.

## Просмотр

Локальная веб-панель только для чтения использует сервисные запросы и слушает исключительно `127.0.0.1`. Её стиль — редакционный операционный журнал: компактная таблица, крупные числовые счётчики, контрастные статусы и отдельная карточка с историей. Доступны поиск и фильтр по статусу, переход к документам задачи через безопасные ссылки. Ввод, запуск команд и изменение состояния через HTTP отсутствуют. CLI/JSON остаются машинным и резервным способом просмотра.

## Проверка

Тесты покрывают жизненный цикл, запрет неверных переходов, версии, готовность и устаревшие артефакты, атомарный claim двух исполнителей, истечение lease, восстановление после ошибок, события, фильтры, экранирование HTML и отсутствие HTTP-мутаций. До подключения Graph Runtime его ссылки остаются внешними идентификаторами; сервис не подменяет состояние запуска.
