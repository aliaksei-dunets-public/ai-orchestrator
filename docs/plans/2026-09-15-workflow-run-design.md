# Первый срез Workflow Run

**Статус:** исторический дизайн, заменён [решением для агента в реальном времени](2026-09-15-realtime-runtime-design.md), 2026-09-15. Обязательное устойчивое хранилище не входит в v1; остальные предложения ниже не являются актуальными требованиями.

## Варианты

1. Последовательный устойчивый запуск с контрольной точкой после узла — рекомендуемый минимальный вариант. Позволяет диагностировать сбои без проектирования параллельных ветвей.
2. Параллельный граф сразу — больше возможностей, но сложнее владение работой, объединение результатов и восстановление; отложен.
3. Запуск только в памяти — проще прототип, но не удовлетворяет требованию устойчивого продолжения; не рекомендуется.

## Предложение

[Кандидат контракта](../architecture/workflow-run.md) определяет логическую модель запуска и попытки, состояния, оболочку результата, владение маршрутизацией и безопасные повторы. Он не выбирает файловый формат, не добавляет runtime и не меняет Task Manager.

Предметные исходы узлов сохраняются; единая оболочка не заменяет контракты Plan Review, Preflight и других операций. Родительский граф владеет маршрутом. Неоднозначный внешний эффект требует проверки, а не автоматического повторного исполнения.

## Последовательность

Подтвердить минимальный последовательный v1. Затем согласовать точный протокол ожидания и восстановления с текущим Task Manager. После этого определить схемы артефактов, хранилище runtime и предметные тесты до реализации.

## Проверка этого среза

Сверить ссылки и документационные границы. Функциональная проверка отложена до реализации. Подтверждение архитектуры не означает готовность runtime; принцип [протокола ожидания](../architecture/workflow-pause-resume.md) согласован, детали координации остаются кандидатом.
