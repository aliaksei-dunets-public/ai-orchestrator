# Выделение Task Manager Service в самостоятельный пакет

**Статус:** реализованное решение, 2026-09-14. Размещение полного skill и документации уточнено в [решении о границах пакетов](2026-09-14-package-boundaries-design.md): они теперь входят в wheel, а корневой skill — указатель.

## Граница

В рамках текущего репозитория создаётся устанавливаемый Python-пакет `packages/task-manager/`. Имя дистрибутива — `orchestrator-task-manager`, имя импорта — `orchestrator_task_manager`. В пакет переходят SQLite-сервис, JSON CLI и локальная панель. Он не импортирует `orchestrator` и не требует Graph Runtime, Task Creator или платформенного адаптера. Хранилище по умолчанию остаётся в `.orchestrator/state/tasks.sqlite3` относительно явно указанного целевого проекта; версия схемы и существующие задачи не меняются.

Публичный Python-вход — `from orchestrator_task_manager import TaskManagerService, TaskError`. Команды `orchestrator-tasks` и `orchestrator-tasks-web` предоставляют CLI и панель после установки. Orchestrator будет потребителем этого пакета, а не владельцем его реализации. Старые модули `orchestrator.task_manager`, `orchestrator.task_cli` и `orchestrator.task_web` удаляются из активного ядра; внутренние тесты и инструкции переходят на пакетные импорты и команды. Откат состояния БД в рамках выделения не требуется, поскольку формат сохраняется.

## Skill

Проектный skill `orchestrator-task-manager` обнаруживается через `.agents/skills/` и версионируется. Полный пример теперь входит в пакет; корневой skill лишь направляет к нему. Skill указывает, как определить корень проекта, использовать CLI для обычного ввода/чтения, Python API с `expected_version` для защищённых переходов, проверять историю и состояние после мутации и никогда не писать в SQLite напрямую. Он не подменяет решение пользователя о содержании задачи, приёмке или отмене и не обещает работу Graph Runtime.

Во внешнем проекте подключённое ядро содержит исходник skill, но Codex автоматически ищет навыки лишь в `.agents/skills` текущего проекта и родительских каталогах. Поэтому инструкция онбординга будет явно направлять агента к skill внутри подключённого репозитория; отдельную установку навыка в целевой проект можно добавить позже как версионируемый шаг онбординга.

## Проверка

Существующие предметные тесты должны пройти с новым импортом. Дополнительно проверяются установка пакета без ядра, работа консольных команд на временном проекте, отсутствие импорта `orchestrator` и валидность skill. В документации фиксируются установка, независимое использование и границы первого среза.
