# Укрепление Task Manager и агентского интерфейса

**Статус:** дизайн реализации, разрешённой пользователем 2026-09-16 после аудита; задача TASK-0023.

## Цель и решение

Стабильный автономный Task Manager должен давать агенту предсказуемые ошибки, сохранять согласованность данных и выполнять типовые операции через CLI. Пользователь явно разрешил этот дополнительный срез; последовательность Graph Runtime не меняется.

Рассмотрены три подхода: только исправления сервиса; исправления плюс тонкий CLI над публичным API; большой рефакторинг моделей и хранения. Выбран второй: первый оставляет неудобные Python-вызовы, третий расширяет объём без доказанного выигрыша.

## Надёжность и скорость

- Потоковое SHA-256, нормализация всех часов в UTC (naive datetime означает UTC).
- Структурная SQL-фильтрация архива до LIMIT, SQL summary без загрузки карточек. На SQLite без JSON1 используется зарегистрированная совместимая функция.
- Экспорт и диагностика читают единый транзакционный снимок. Диагностика избегает отдельного SELECT колонок для каждой задачи.
- Файловые ошибки документов сохраняют смысл validation/guard; restore, backup и export дают TaskError с полезными деталями и очищают только собственные временные файлы.
- Чтение документа проверяет хеш именно возвращаемых байтов, чтобы исключить подмену между хешированием и чтением.

## Агентский интерфейс

CLI сохраняет JSON по умолчанию и коды выхода 0/1/2. Аргументы --project и --format допускаются до и после команды. Мутации читают текущую версию либо используют явно переданную --expected-version; конфликт не повторяется автоматически.

Команды покрывают подготовку, артефакты, ready, claim/renew/release/recover, ссылки на сессию, блокеры, решения, приёмку и отмену. Они вызывают только публичный API и сохраняют guards. Метаданные артефактов передаются JSON-объектом. Операционные ID доступны там, где их поддерживает API.

accept_task — новая атомарная операция регистрации явной приёмки текущей ревизии и завершения. Требуются candidate_revision и completion_decision_ref; при неуспешном guard не сохраняется даже решение. Событие task_completed включает решение о приёмке. Старые record_user_decision и complete_task сохраняются.

summary по умолчанию исключает архив и tombstone, --include-archived включает архив; отдельно возвращаются количество архивных и удалённых задач. Табличный режим предназначен для чтения человеком; ошибки всегда JSON. TypeError неправильного вызова Python остаётся стандартным.

## Проверки и границы

Регрессии проверяют структурный архив и пагинацию, экспорт под конкурентной записью, UTC, удаление/подмену документов, файловые отказы, атомарность приёмки, версии и CLI. Замеры выполняются одинаковой командой до и после на временных проектах с 100/500/1000 задач; сохраняются p50/p95, время создания, размер БД и SHA-256 1KB/1MB/100MB.

Обновляются контракт, гайд, skill, project-status и worklog. Runtime и Artifact Repository не реализуются этим срезом. Финальная карточка остаётся awaiting_acceptance до отдельной пользовательской приёмки результата.
