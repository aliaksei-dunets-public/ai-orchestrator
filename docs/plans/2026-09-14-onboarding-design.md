# Проект: первичная настройка целевого проекта

**Статус:** согласовано для реализации первого среза (2026-09-14).

## Решение

Доставка ядра и настройка проекта разделены. Во внешнем проекте ядро находится в `tools/graph-orchestrator/` как Git submodule или копия подготовленного пакета. В режиме self-hosted корень ядра совпадает с корнем целевого проекта; вложенная копия не создаётся. Способ доставки не меняет контракт настройки.

Агент читает проект и готовит краткие сведения о нём: название, назначение, команды проверок и ограничения. Детерминированный инструмент получает эти сведения, целевой путь и путь ядра. Команда `preview` не меняет целевой проект: она строит точный план файлов, показывает diff и хеш плана. Команда `apply` принимает тот же план и явно подтверждённый хеш, проверяет, что затрагиваемые файлы не изменились, и только затем пишет их. После записи она валидирует результат; при обычной ошибке восстанавливает файлы, изменённые этим запуском.

## Владение файлами

Инструмент создаёт версионируемые `.graph-orchestrator/project.json` и `.graph-orchestrator/project-context.md`. Если они уже существуют с другим содержимым, первый срез останавливается и не перезаписывает их. Во внешнем проекте он добавляет ограниченный маркированный блок в `AGENTS.md`; содержимое вне блока сохраняется. Для `.orchestrator/` добавляется правило игнорирования только если его ещё нет. Runtime-состояние `.orchestrator/` не создаётся до появления соответствующего runtime.

## Границы и проверки

План фиксирует хеши лишь затрагиваемых файлов, а не всего репозитория. Символические ссылки и выход за пределы целевого проекта запрещены. Проверяются повторное применение, изменение файла между preview/apply, конфликт владения, self-hosting, внешний проект, отказ записи и откат. Первый срез не гарантирует транзакционность при аварийном завершении процесса между несколькими заменами файлов; до следующего этапа восстановление такого случая выполняется по Git или резервной копии пользователя.
