# Решение: исключить отдельную спецификацию задачи

**Статус:** реализовано в `TASK-0012`.

## Решение

Отдельный файл `.orchestrator/tasks/TASK-xxxx/specification.md` больше не будет частью обязательного workflow Task Manager и не будет требоваться для перехода `preparing → ready`. Роль сохраняется только для чтения и совместимости со старыми карточками.

Каноническое определение задачи хранится в карточке Task Manager:

- `original_request`;
- `objective`;
- `acceptance_criteria`;
- `constraints`;
- `definition_version`.

## Оставшиеся уровни

- `docs/plans/` содержит архитектурный дизайн и обоснование решений проекта;
- `.orchestrator/tasks/TASK-xxxx/plan.md` содержит конкретный план реализации задачи;
- Task Manager хранит lifecycle, версии, события, артефакты и пользовательскую приёмку.

## Изменения для реализации

В отдельной задаче потребуется:

1. изменить `ready_guard`, чтобы обязательными были `plan`, `plan_review` и `execution_package`;
2. изменить binding Execution Package: он будет ссылаться на хеш плана и ревизию источника без хеша спецификации;
3. обновить миграцию/контракт, CLI, skill и документацию;
4. перенести существующие задачи на новый lifecycle без потери истории;
5. добавить тесты для задач без `specification.md`.

Отдельный файл требований может остаться обычным необязательным legacy-артефактом для крупных интеграций, но не будет защитным условием Task Manager.
