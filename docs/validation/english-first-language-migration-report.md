# English-first language migration validation report

**Date:** 2026-07-28
**Task:** TASK-0004
**Status:** accepted implementation evidence

## Canonical path migration

Architecture and Task Layer specifications are now canonical at
`docs/specifications/orchestrator-specification.md` and
`docs/specifications/task-layer-specification.md`. The previous Russian
specifications remain preserved as `*-ru.md` historical baselines and are not
graph sources. Russian maintainer plans and validation reports are preserved as
`.ru.md` baselines; their same-name English files are canonical.

## User documentation policy

README, deployment, development-environment, memory/knowledge, migration, and
optional Python review documentation use separate English canonical and Russian
companion files. Each pair has `language`, reciprocal `translation_of`, valid
local links, and matching code-fence counts. Russian companions are reader-only
and excluded from Knowledge Graph retrieval.

## Graph-source policy

`config/language-policy.json` is shared by inventory, source authority, graph
writes, onboarding, and retrieval. English canonical sources are eligible;
Russian companions, mixed/unknown documents, generated projections, releases,
aliases, and missing/invalid provenance are rejected before graph writes.
Retrieval rechecks current language eligibility and source digests, while empty
stores remain valid no-ops.

## Compatibility and rollback

Task Registry, Task Context, Memory, Knowledge Graph, CLI, and release schemas
remain version 1 compatible. Language metadata is additive. To roll back,
restore the previous canonical path mapping, rebuild indexes from validated
English sources, regenerate skill projections from `skills/`, and retain Russian
companions as non-canonical documentation until corrected.
