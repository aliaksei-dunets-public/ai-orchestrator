# План миграции Orchestrator

Графовый фреймворк пока не реализован. Документы в этом каталоге — проектные материалы; их статус указан в каждом файле. Разработка идёт последовательно. Этап завершён только тогда, когда его контракты, код, тесты, русскоязычная документация и необходимые гайды согласованы.

1. **Граница репозитория (выполнено):** сохранить прежний продукт, старое локальное состояние и релизы в `obsolete/`; перенести проектные документы нового подхода в `docs/`; обновить инструкции в корне и проверить сохранность файлов и ссылок.
2. **Первичная настройка проекта (первый срез реализован):** отдельный пакет Onboarding содержит безопасный протокол preview/apply для внешнего проекта и self-hosting. Сборка общего пакета ядра, проверка его установки и обновления остаются будущими работами. Действующий контракт: [первичная настройка](architecture/onboarding.md), [инструкция](guides/onboarding.md).
3. **Согласование и первый runtime-срез (в процессе):** [граница хранения](architecture/state-and-storage.md), [граф агента в реальном времени](architecture/workflow-run.md) и [пауза в сессии](architecture/workflow-pause-resume.md) согласованы. Реализован первый входной срез [Request Router → Task Creator](guides/request-flow.md), работающий через публичный Task Manager API. Незавершённая последовательность: TASK-0002 — контракты Graph Runtime, TASK-0003 — in-memory runtime, TASK-0004 — тесты и документация runtime. Состояние процесса — в памяти. Возможная [будущая координация нескольких запусков](architecture/runtime-coordination.md) вынесена отдельно и сейчас не реализуется. Этап целиком не завершён.
4. **Детерминированная основа (Task Manager Service — первый срез):** отдельный устанавливаемый пакет содержит SQLite-хранилище задач, события, защищённые переходы, версионируемый реестр миграций схемы, идемпотентность, backup/export/restore, архивацию с retention и локальную панель по [действующему контракту](architecture/task-manager.md). Репозиторий артефактов и движок переходов графа остаются в работе следующих этапов.
5. **Подготовка задачи:** после TASK-0002–0004 реализовать Artifact Repository (TASK-0014), затем контекст, анализ, планирование, проверку плана и устойчивую границу `ready` (TASK-0015); структурированная карточка Task Manager является каноническим определением задачи.
6. **Исполнение задачи:** TASK-0016 реализует preflight, claim/lease и work units; TASK-0017 — ревью, тесты, документацию, финальную проверку и приёмку пользователем.
7. **Знания и интеграции:** после TASK-0017 согласовать и реализовать Project Knowledge Map (TASK-0019–0020), затем собрать устанавливаемое ядро (TASK-0021). Внешний Task Tracker Adapter (TASK-0018) отложен на будущее и не блокирует локальный v1.
8. **Сквозная проверка:** TASK-0022 выполняет сценарные, восстановительные, конкурентные, защитные и межплатформенные тесты локального v1 и публикует свидетельства готовности релиза.

Полная карта зависимостей и источников: [backlog развития v1](plans/2026-09-16-orchestrator-roadmap-backlog-design.md).

На каждом этапе фиксируй выполненные работы, результаты проверок и исправления документации. Не переноси старый код неявно: нужный навык, идея или контракт из `obsolete/` должны быть осознанно адаптированы и проверены на соответствие новым контрактам.
