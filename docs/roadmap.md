# План миграции Orchestrator

**Статус:** дизайн поэтапной миграции подтверждён пользователем 2026-09-17; первый process API срез реализован, остальные implementation contracts создаются по этапам. Карточки задач — в Task Manager, этот документ не меняет их статусы.

Минимальные Graph Runtime, Artifact Repository и Preparation Workflow сохраняют callback API; новые AgentGraphRuntime/AgentPreparation принимают явные results, а Knowledge Service имеет реальный Graphify adapter. Полного исполнения и portable Agent delivery пока нет. Дальнейшая разработка следует [Orchestrator Agent](architecture/agent-centric-orchestration.md) и [Project Knowledge Service](architecture/project-knowledge-service.md), а не развитию Python reasoning controller. Task Manager сохраняется без изменений. Этап завершён только тогда, когда код, контракты, тесты, документация и гайды согласованы.

## Сохраняемые реализованные этапы

1. **Граница репозитория (выполнено):** сохранить прежний продукт, старое локальное состояние и релизы в `obsolete/`; перенести проектные документы нового подхода в `docs/`; обновить инструкции в корне и проверить сохранность файлов и ссылок.
2. **Первичная настройка проекта (первый срез реализован):** отдельный пакет Onboarding содержит безопасный протокол preview/apply для внешнего проекта и self-hosting. Сборка общего пакета ядра, проверка его установки и обновления остаются будущими работами. Действующий контракт: [первичная настройка](architecture/onboarding.md), [инструкция](guides/onboarding.md).
3. **Согласование и первый runtime-срез (выполнено):** [граница хранения](architecture/state-and-storage.md), [граф агента в реальном времени](architecture/workflow-run.md), [пауза в сессии](architecture/workflow-pause-resume.md) и [пользовательский guide](guides/workflow-runtime.md) согласованы. Реализованы первый входной срез [Request Router → Task Creator](guides/request-flow.md), core in-memory runtime одной сессии (TASK-0003), предметные тесты и документация (TASK-0004 завершена). Состояние процесса — в памяти. Возможная [будущая координация нескольких запусков](architecture/runtime-coordination.md) вынесена отдельно и сейчас не реализуется. Интеграционное связывание с Task Manager и Artifact Repository относится к следующим этапам.
4. **Детерминированная основа (Task Manager Service — первый срез):** отдельный устанавливаемый пакет содержит SQLite-хранилище задач, события, защищённые переходы, версионируемый реестр миграций схемы, идемпотентность, backup/export/restore, архивацию с retention и локальную панель по [действующему контракту](architecture/task-manager.md). Дополнительная TASK-0023 разрешена пользователем для надёжности, скорости диагностики и агентского CLI; [результаты](reports/2026-09-16-task-manager-hardening.md) отделены от дальнейшей реализации графа. TASK-0024 разрешена для внутреннего разделения пакета с сохранением API и схемы; [результаты разделения](reports/2026-09-17-task-manager-modularization.md) не означают реализацию runtime. Artifact Repository и минимальный in-memory движок переходов уже реализованы; подготовка и исполнение развиваются следующими срезами.
5. **Подготовка задачи:** Artifact Repository v1 реализован, прошёл независимый Luna High аудит с исправлениями и принят в TASK-0014 (completed, version 21). TASK-0015 реализует минимальные контекст, анализ, планирование, проверку плана и устойчивую границу `ready`; принята пользователем и завершена (version 18). Структурированная карточка Task Manager является каноническим определением задачи. [Контракт](architecture/preparation-workflow.md), [guide](guides/preparation-workflow.md), [отчёт](reports/2026-09-17-preparation-workflow.md).
## Новая последовательность миграции

1. **Архитектурная оценка и согласование (дизайн подтверждён):** [baseline и миграционная матрица](reports/2026-09-17-agent-centric-graphify-assessment.md), [подтверждённый дизайн](plans/2026-09-17-agent-centric-graphify-migration-design.md). Выбран Graphify-Labs/graphify и локальный code-only первый корпус без глобальных hooks/semantic документов. TASK-0027 остаётся общей задачей миграции, не completed.
2. **Agent-facing process primitives (TASK-0028, приняты пользователем, completed v18):** [AgentGraphRuntime contract](architecture/agent-runtime-contract.md), [guide](guides/agent-runtime.md), [отчёт](reports/2026-09-17-agent-runtime-v1.md). Явные результаты, допустимые actions, process revision, definition/wait guards, история и limits; старый runtime сохранён. Новый код не запускает planning/context callbacks вместо агента и не меняет Task Manager.
3. **Подготовка агентом (TASK-0029, принята, completed v18):** [AgentPreparation](architecture/agent-preparation.md), [инструкции и guide](guides/agent-preparation.md), [отчёт](reports/2026-09-18-agent-preparation-v1.md). Явные semantic results, artifacts и ready без claim; pending barrier/history reconciliation. Installed skill/MCP facade — последующая поставка.
4. **Project Knowledge Service / Graphify (TASK-0030, принята пользователем, completed v18):** [контракт](architecture/project-knowledge-service.md), [guide](guides/project-knowledge.md), [отчёт](reports/2026-09-18-project-knowledge-service-v1.md). Snapshot dirty/untracked, immutable full-rebuild refresh, provenance, bounded query_graph-only MCP; failed refresh сохраняет старый граф. Проверены pinned Python/TSX/Vue/Unicode fixtures и initial load проекта. Workflow integration и onboarding profile — последующие этапы.
5. **Исполнение агентом:** TASK-0016 реализует [preflight и work units](architecture/agent-execution.md), принята пользователем и completed v19; [guide](guides/agent-execution.md), [отчёт](reports/2026-09-18-agent-execution-v1.md). TASK-0017 уточнена и остаётся created: явные review/tests/documentation/knowledge refresh/final validation и readiness/acceptance. Смысловую маршрутизацию выполняет агент, проверки — primitives.
6. **Поставка:** уточнить TASK-0021 под agent/core bundle и host-neutral adapters; расширить onboarding явным подключением агентских instructions и knowledge profile без скрытых установок и глобальных hooks.
7. **Сквозная проверка:** уточнить TASK-0022; внешний onboarding, полный task lifecycle, stale plan/graph, waits, неопределённые эффекты, permission boundaries и проверяемая совместимость. Межсессионное recovery не обещается до отдельного checkpoint-среза.

TASK-0019–0020 уточнены под service/provider integration вместо собственной PKM storage/extraction engine; created, definition v2/v4 соответственно. TASK-0018 остаётся отложенной внешней tracker integration. ABAP, worker pool и расширенная memory service не блокируют локальный v1. Уже completed этапы не переоткрываются, TASK-0024 не получает приёмку автоматически. В текущем срезе публичным API уточнены TASK-0016–0017 и TASK-0019–0022; original_request сохранён. TASK-0021–0022 created definition v2/v4. TASK-0018 не менялась.

[Прежний backlog v1](plans/2026-09-16-orchestrator-roadmap-backlog-design.md) сохраняет историю исходной карты зависимостей; его controller-centric порядок больше не является планом новой реализации.

На каждом этапе фиксируй выполненные работы, результаты проверок и исправления документации. Не переноси старый код неявно: нужный навык, идея или контракт из `obsolete/` должны быть осознанно адаптированы и проверены на соответствие новым контрактам.
